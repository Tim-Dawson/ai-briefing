AWS SAA-C03 Quick Reference Guide

June 16th, 2026 7 min read

At a Glance

  • Use this for: last-minute refresh on the AWS terms and services that show up repeatedly in SAA-C03 questions.
  • Exam mindset: pick the answer that is secure, resilient, managed, scalable, and not absurdly expensive.
  • Quick pattern memory: web apps usually mean ALB + Auto Scaling + multi-AZ + RDS/Aurora/S3. Async processing usually means SQS. Global delivery usually means CloudFront.
  • Security memory: roles not access keys, private subnets for databases, KMS for encryption, security groups are stateful, NACLs are stateless.
  • Storage memory: S3 = object, EBS = block, EFS = shared file.

Region

A separate geographic area such as `eu-west-1`. If the exam says a system must survive a regional outage, you need multi-Region thinking.

Availability Zone (AZ)

A separate data centre location inside a Region. If the exam says high availability, AWS often expects multi-AZ.

VPC

Your private network in AWS. It contains subnets, route tables, security groups, and networking controls.

Public Subnet

A subnet with a route to an Internet Gateway. Internet-facing load balancers often live here.

Private Subnet

A subnet without direct internet access. App servers and databases usually belong here.

Internet Gateway

Connects a VPC to the internet for public resources.

NAT Gateway

Lets resources in private subnets make outbound internet calls without being directly reachable from the internet.

VPC Endpoint

Private connection from a VPC to AWS services like S3 or DynamoDB without going over the public internet. In exam questions, this is often better than paying for NAT just to reach S3.

IAM

AWS identity and access system. Controls who can do what.

IAM Role

Temporary credentials for AWS services or federated users. The exam strongly prefers roles over hardcoded access keys.

Least Privilege

Give only the minimum permissions needed. If one answer grants huge blanket access and another grants narrow access, the narrow one is usually correct.

Security Group

Stateful virtual firewall attached to instances or ENIs. Main point to remember: stateful.

Network ACL (NACL)

Stateless subnet-level firewall. Main point to remember: stateless and supports allow/deny rules.

KMS

AWS Key Management Service. Used to control encryption keys for services like S3, EBS, and RDS.

RTO and RPO

These two values often tell you which disaster recovery design AWS wants.

  • RTO: how fast you must recover
  • RPO: how much data you can afford to lose

EC2

Virtual servers in AWS. Use EC2 when you need OS-level control, custom software, or long-running compute.

Exam clue: if the requirement says minimal operational overhead, EC2 is often not the best answer.

Auto Scaling

Automatically adds or removes EC2 instances based on demand.

Common use: web app must scale during traffic spikes.

Lambda

Serverless event-driven compute. Good for short-lived code triggered by uploads, API calls, or events.

Exam clue: bursty workloads, event processing, minimal ops.

ECS

AWS container orchestration service.

Fargate

Runs containers without managing servers.

Exam clue: if the app uses containers but the business wants minimal ops, ECS on Fargate is often the answer.

EKS

Managed Kubernetes. Use it when the question specifically needs Kubernetes.

ALB

Application Load Balancer. Layer 7 HTTP/HTTPS balancing with path-based and host-based routing.

Use for: web applications and microservices.

NLB

Network Load Balancer. Layer 4 TCP/UDP balancing with very high performance and static IP support.

CloudFront

AWS CDN. Caches content close to users around the world.

Exam clue: lower latency for global users, reduced origin load, static assets, media delivery.

Route 53

AWS DNS service.

Useful routing policies:

  • Simple: one endpoint
  • Weighted: split traffic by percentage
  • Latency: send users to lowest-latency Region
  • Failover: send traffic to backup if primary fails

S3

Object storage. Very durable and massively scalable.

Use for: files, backups, logs, static website assets, media, archives.

Memory peg: S3 is not a normal mounted disk for your app server.

EBS

Block storage attached to EC2.

Use for: boot volumes and low-latency disks for one instance.

Memory peg: tied to one AZ.

EFS

Managed shared file system for Linux workloads.

Use for: multiple EC2 instances needing access to the same files.

FSx

Managed specialised file systems, such as Windows or high-performance file workloads.

RDS

Managed relational database service.

Use for: SQL, transactions, traditional relational apps.

Aurora

AWS-managed high-performance relational database compatible with MySQL/PostgreSQL.

Exam clue: relational + high availability + strong performance + managed operations.

DynamoDB

Managed NoSQL key-value/document database.

Use for: very low-latency, high-scale access patterns with known keys.

Exam clue: user profiles, sessions, carts, event metadata, huge scale.

ElastiCache

Managed in-memory cache.

Use for: reduce database load, improve response time, cache hot data, store fast session state.

Redshift

Data warehouse for analytics. Usually appears when the question is about large-scale analytics, reporting, or BI.

SQS

Queue service.

Use for: decoupling systems, buffering bursts, async processing.

Memory peg: if the backend should not fall over during spikes, think SQS.

SNS

Pub/sub notification service.

Use for: fan-out to multiple subscribers.

EventBridge

Event bus with rule-based routing.

Use for: event-driven integration across services and applications.

Step Functions

Workflow orchestration service.

Use for: multi-step processes, retries, branching logic, ordered Lambda workflows.

Secrets Manager

Stores secrets such as passwords and API keys.

Exam clue: if the question says automatic rotation, pick Secrets Manager.

Systems Manager Parameter Store

Stores configuration values and sometimes secrets, often for simpler use cases.

ACM

AWS Certificate Manager.

Use for: TLS/SSL certificates for HTTPS endpoints like ALBs and CloudFront.

WAF

Web Application Firewall.

Use for: block malicious HTTP/S requests such as SQL injection or cross-site scripting attempts.

Shield

DDoS protection service.

Memory peg: WAF filters web traffic, Shield helps with DDoS protection.

Scalable Web App

  • Route 53
  • CloudFront optional
  • ALB
  • EC2 Auto Scaling across multiple AZs
  • RDS/Aurora Multi-AZ
  • S3 for static assets

Serverless Event Flow

  • S3 upload or API call
  • Lambda runs processing
  • store output in DynamoDB or S3
  • notify via SNS or route via EventBridge

Decoupled Worker System

  • producer sends messages to SQS
  • workers process messages later
  • system absorbs spikes safely

S3 vs EBS vs EFS

  • S3: object storage
  • EBS: block storage for one EC2 instance
  • EFS: shared file storage

RDS vs Aurora vs DynamoDB

  • RDS: managed relational database
  • Aurora: stronger AWS-managed relational answer for many HA/performance scenarios
  • DynamoDB: NoSQL at huge scale with very low latency

SQS vs SNS vs EventBridge

  • SQS: queue work
  • SNS: broadcast messages
  • EventBridge: route events

ALB vs NLB

  • ALB: HTTP/HTTPS app traffic
  • NLB: TCP/UDP high-performance traffic

NAT Gateway vs VPC Endpoint

  • NAT Gateway: outbound internet from private subnets
  • VPC Endpoint: private access to AWS services

Last-Minute Exam Triggers

If the question says this, think that:

  • high availability -> multi-AZ
  • disaster recovery across Regions -> multi-Region DR pattern
  • minimal operational overhead -> managed or serverless service
  • shared files across instances -> EFS
  • object storage for files -> S3
  • absorb traffic spikes -> SQS
  • relational + managed -> RDS or Aurora
  • very fast NoSQL at scale -> DynamoDB
  • global low-latency content delivery -> CloudFront
  • secret rotation -> Secrets Manager
  • private access to S3 -> VPC endpoint

Final Memory Pegs

  • Roles, not access keys
  • Security groups are stateful
  • NACLs are stateless
  • S3 object, EBS block, EFS shared
  • ALB for web, NLB for TCP/UDP
  • SQS queue, SNS fan-out, EventBridge routing
  • RDS/Aurora relational, DynamoDB NoSQL
  • CloudFront global delivery
  • Multi-AZ for HA, multi-Region for Region failure
  • Managed usually beats self-managed on this exam
