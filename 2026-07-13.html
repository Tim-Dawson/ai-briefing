Shared Selective Memory May Be the Missing Layer Between “Stateless Chat” and Useful Agents

What happened: a new paper, Shared Selective Persistent Memory for Agentic LLM Systems, was posted on July 13, 2026. The authors argue that most agent systems persist either too little context or far too much. Their proposed alternative keeps only four reusable categories: task specifications, data schemas, tool configurations, and output constraints, while discarding session-specific reasoning traces. The implementation is tested in a collaborative workspace platform that works across CSV, SQL, REST APIs, and MCP servers.

Why it matters: this is one of the more practically useful agent-architecture ideas to land today because it attacks a common failure mode directly. Teams often assume “more history” means “better continuity,” but the paper reports the opposite: naive full-history persistence degrades task completion to 71%, while selective memory reaches 96%, versus 79% with no memory at all. Just as interesting, the zero-token refresh pattern removes repeated LLM calls for recurring updates and cuts task time by 14x. The deeper lesson is that memory should be treated as a designed systems layer, not a transcript dump. For anyone building agents around tool use or MCP-style integrations, that is a very actionable framing.

Source: arXiv:2607.09493

GATS Suggests Better Agent Planning Might Come from Fewer Live Model Calls, Not More

What happened: GATS: Graph-Augmented Tree Search with Layered World Models for Efficient Agent Planning also appeared on July 13, 2026. The core move is to separate planning from continuous LLM invocation by using a three-layer world model: exact symbolic action matching, statistics learned from execution logs, and LLM-based prediction only for unknown actions. In the reported experiments, GATS eliminates LLM calls during planning entirely.

Why it matters: the headline numbers are hard to ignore. The paper reports 100% success on its synthetic planning tasks, versus 92% for LATS and 64% for ReAct, and 100% success across 12 stress-test scenarios while using zero LLM calls per task during planning, compared with 37 for LATS. Even if those numbers soften under broader replication, the design point is the interesting part: strong agent behavior may come from turning the model into a fallback layer inside a tighter planner, rather than asking it to improvise every branch in real time. That is a useful corrective to the current habit of treating “more reasoning tokens” as a universal answer.

Source: arXiv:2607.08894

Frontier Agents Still Look Fragile on Truly Long-Horizon Terminal Work

What happened: Long-Horizon-Terminal-Bench: Testing the Limits of Agents on Long-Horizon Terminal Tasks with Dense Reward-Based Grading introduces 46 terminal tasks designed to be much closer to real work than short benchmark puzzles. The tasks span experiment reproduction, software engineering, multimodal analysis, scientific computing, and more, with fine-grained subtasks so the benchmark can measure partial progress instead of only pass/fail outcomes.

Why it matters: the results are a useful cold shower. The paper reports that agents average 9.9 million tokens, 231 episodes, and 85.3 minutes per run, yet even the best tested model reaches only 15.2% pass@1 at a 0.95 partial-reward threshold and 10.9% at a perfect-reward threshold. Average performance across models is lower still. The practical lesson is that long-horizon agent progress is still bottlenecked by planning drift, context management, and iterative debugging, not by a lack of short-form competence. If you are evaluating coding or ops agents, this is a reminder that “can solve toy tasks” and “can finish real terminal work” remain very different claims.

Source: arXiv:2607.08964

Local Inference Tuning Is Quietly Becoming a Model-Quality Issue

What happened: Attention to Detail: Evaluating Energy, Performance, and Accuracy Trade-offs Across vLLM Configurations examines three concrete serving choices in vLLM: attention kernel type, prefix caching, and chunked prefill. The authors test all combinations across five open-weight LLMs and five inference tasks, yielding 9,000 runs and 93,600 measurements.

Why it matters: this is exactly the kind of paper local-inference teams need more of, because it shifts the conversation from vague optimization folklore to measured trade-offs. The headline finding is not simply that settings affect speed and energy. It is that they can also affect accuracy, and that no single configuration wins everywhere. Model choice still dominates the global trade-off surface, but configuration determines where you sit on that frontier. In plain English: serving-stack knobs are part of model behavior now, not just deployment plumbing. Anyone running open models locally or through self-hosted APIs should treat inference configuration as an evaluation variable.

Source: arXiv:2607.09172

One Thing to Dig Into

If you read just one item today, make it Shared Selective Persistent Memory for Agentic LLM Systems. It has the most immediately useful systems insight in the set: agents do not merely need memory, they need aggressively curated memory that preserves reusable constraints and tool context without hauling stale reasoning around forever.
